# Reminder System — Firestore + Alarm Scheduling

## Overview

The reminder system has been completely refactored to use **Firestore as the persistent backend** instead of mock data. Reminders are automatically synced with local alarm scheduling via the existing NotificationService.

**All mock reminder data has been removed.** Reminders load exclusively from Firestore at app startup.

---

## Architecture

### Data Flow

```
Firestore (users/{uid}/reminders/{reminderId})
    ↓
ReminderFirestoreService (CRUD operations)
    ↓
ReminderProvider (state management + alarm orchestration)
    ↓
NotificationService (native alarm scheduling)
    ↓
Local notifications (even when app is closed)
```

### File Structure

- **`lib/services/reminder_firestore_service.dart`** — Firestore CRUD operations
- **`lib/providers/reminder_provider.dart`** — State management + alarm orchestration
- **`lib/data/models/models.dart`** — `Reminder` class with Firestore serialization
- **`lib/features/reminders/reminders_screen.dart`** — UI (with empty state)
- **`lib/services/notification_service.dart`** — Existing alarm scheduling (unchanged)

---

## Firestore Schema

```
users/
  {uid}/
    reminders/
      {reminderId}/
        - title: String (required, immutable)
        - dose: String (e.g., "1 tablet", "2 puffs")
        - time: String (e.g., "8:00 AM", "9:30 PM")
        - schedule: String ("Daily" | "Weekdays" | "Mon · Wed · Fri" | "Custom")
        - instructions: String (optional, e.g., "with food")
        - addedBy: String ("you" | "MedAI")
        - status: String ("pending" | "taken" | "snoozed" | "skipped")
        - streakDays: int (default: 0)
        - enabled: bool (default: true) — controls alarm scheduling
        - snoozeLabel: String | null
```

### Notes

- **Document ID** (`reminderId`) is auto-generated by Firestore
- **title** is locked after creation (no rescheduling on title change)
- **enabled** flag controls whether the alarm is scheduled
- Status changes are persisted but **do NOT reschedule** alarms
- Time/schedule/dose changes **DO reschedule** alarms (via `update()`)

## API Reference

### ReminderProvider

#### Initialization

```dart
// Automatic on app startup via MultiProvider in main.dart
// Loads all enabled reminders from Firestore and reschedules alarms
ReminderProvider();
```

#### Create

```dart
await reminderProvider.add(Reminder(
  title: 'Ibuprofen',
  dose: '200 mg',
  time: '8:00 AM',
  schedule: 'Daily',
  instructions: 'With food',
));
// → Saves to Firestore
// → Schedules alarm
// → Updates UI
```

#### Read

```dart
final reminders = reminderProvider.reminders; // List<Reminder>
final nextDose = reminderProvider.nextDose; // Reminder?
```

#### Update

```dart
await reminderProvider.update(reminder,
  dose: '400 mg',
  time: '9:00 AM',
  schedule: 'Weekdays',
);
// → Updates Firestore document
// → Cancels old alarm
// → Schedules new alarm
// → Updates UI
```

#### Delete

```dart
await reminderProvider.remove(reminder);
// → Deletes from Firestore
// → Cancels all alarms for this reminder
// → Updates UI
```

#### Enable / Disable

```dart
await reminderProvider.enable(reminder);
// → Sets enabled=true in Firestore
// → Schedules alarm

await reminderProvider.disable(reminder);
// → Sets enabled=false in Firestore
// → Cancels alarm
```

#### Status Changes (no alarm rescheduling)

```dart
reminderProvider.take(reminder);     // Marks as taken
reminderProvider.untake(reminder);   // Reverts to pending
reminderProvider.snooze(reminder);   // Snoozes 10 min
reminderProvider.skip(reminder);     // Marks as skipped
// → Persist to Firestore
// → No alarm changes
```

#### Statistics

```dart
reminderProvider.takenCount;    // int
reminderProvider.skippedCount;  // int
reminderProvider.bestStreak;    // int (max streak across all reminders)
reminderProvider.adherencePct;  // int (0-100, this week)
```

#### Other

```dart
reminderProvider.isLoading;     // bool (during Firestore operations)
await reminderProvider.refresh(); // Force reload from Firestore
```

### ReminderFirestoreService

**Generally not used directly — all operations go through ReminderProvider.**

```dart
final service = ReminderFirestoreService.instance;

// Fetch all reminders for logged-in user
List<Reminder> reminders = await service.fetchReminders();

// Create new reminder
Reminder? saved = await service.createReminder(reminder);

// Update existing reminder
bool success = await service.updateReminder(reminder);

// Delete by ID
bool success = await service.deleteReminder(reminderId);

// Listen to real-time updates
Stream<List<Reminder>> stream = service.remindersStream();
```

## Alarm Scheduling Details

### Unique Notification IDs

Notification IDs are derived from the reminder's **title** (which is immutable):

```dart
int baseId = (title.hashCode.abs() % 100000) * 10;
```

This ensures:
- **Consistent IDs** across app restarts
- **No duplicates** if the same reminder is scheduled twice
- **One ID per daily reminder** (or one per weekday for recurring schedules)

### Schedule Types

#### Daily

```dart
schedule: 'Daily'
```

- One alarm per day at the specified time
- Repeats every 24 hours
- Uses `matchDateTimeComponents: DateTimeComponents.time`

#### Weekdays

```dart
schedule: 'Weekdays'
```

- Alarms on Mon–Fri at the specified time
- Each weekday has its own alarm ID: `baseId + weekday` (1–5)
- Uses `matchDateTimeComponents: DateTimeComponents.dayOfWeekAndTime`

#### Mon · Wed · Fri

```dart
schedule: 'Mon · Wed · Fri'
```

- Alarms on Mon/Wed/Fri at the specified time
- Each day has its own alarm ID
- Uses `matchDateTimeComponents: DateTimeComponents.dayOfWeekAndTime`

#### Custom

```dart
schedule: 'Custom'
```

- Falls back to **daily** scheduling
- UI accepts custom schedules, but backend schedules daily
- Future: Allow JSON weekday arrays in Firestore

### Alarm Modes

- **Android**: `AndroidScheduleMode.exactAllowWhileIdle` (precise, even in Doze mode)
- **iOS**: Standard `zoned​Schedule` with repeating modes
- **Permissions**: Automatically requested on app startup

### Edge Cases

- **Past time**: If scheduled time has already passed today, the alarm fires tomorrow
- **Timezone changes**: Handled by flutter_timezone; alarms reschedule on timezone change
- **App closed**: Alarms fire as native Android/iOS notifications (OS-level scheduling)
- **Cold start**: All enabled reminders are rescheduled when the app launches

## Notification Integration

### NotificationService (Existing)

The reminder system uses the **existing NotificationService** without modification. No separate notification system is created.

When an alarm fires:

1. FlutterLocalNotifications triggers a native notification
2. If the app is open, `NotificationProvider` logs it to JSON history
3. If the app is closed, tapping the notification opens the app (cold start)
4. Notification taps are routed through `NotificationService._saveFromPayload()`

### Notification Payload

```dart
{
  'title': 'Medicine Reminder',
  'message': 'Time to take Ibuprofen · 200 mg',
  'time': '8:00 AM',
}
```

This payload is saved to the **local JSON notification history** (not Firestore).

## Cold Start Handling

### App Startup Flow

```
main() → Firebase.initialize() → NotificationService.initialize()
  ↓
MultiProvider creates ReminderProvider
  ↓
ReminderProvider._initializeReminders()
  ├─ Fetch all reminders from Firestore
  ├─ Reschedule alarms for each enabled reminder
  └─ Set isLoading = false, notify UI
```

### Recovery from Restart

If the app was **force-closed or crashed**:

1. Alarms still fire (native OS scheduling is independent of app state)
2. Tapping a notification opens the app
3. `NotificationService.initialize()` checks `getNotificationAppLaunchDetails()` for the payload
4. If found, the payload is logged to JSON history
5. `NotificationProvider` refreshes the UI

**No duplicate alarms** are scheduled because:
- Alarm IDs are stable (based on title)
- `scheduleReminder()` always calls `cancelForReminder()` first
- Only enabled reminders are scheduled on cold start

## Error Handling

### Firestore Errors

- User not logged in → Empty reminder list, no operations allowed
- Firestore connection fails → Graceful degradation, retry on next operation
- Permission denied → Logged to console, operation fails silently (handled by provider methods)

### Alarm Scheduling Errors

- Invalid time format → Logged to debug console, reminder not scheduled
- Missing notification permissions → Requested at app startup
- Device doesn't support exact alarms → Falls back to inexact scheduling

### Recovery

- Call `reminderProvider.refresh()` to retry failed operations
- Alarms are rescheduled on every app restart, so temporary glitches are fixed

## User Experience

### Empty State

When a user has no reminders:

- RemindersScreen shows a friendly empty state
- Icon + message + "Create reminder" button
- No stats header, no mock data

### Loading State

While fetching reminders from Firestore:

- RemindersScreen shows a loading spinner
- Usually instant, but delays are visible on slow networks

### Add Reminder

1. User taps FAB → Modal sheet appears
2. User enters title, dose, time, schedule → Taps "Save reminder"
3. Reminder is created in Firestore (ID assigned)
4. Alarm is immediately scheduled (even before modal closes)
5. Modal closes, UI updates (new reminder appears)

### Edit Reminder

1. User taps a reminder card → Modal sheet appears (with pre-filled fields)
2. User edits fields → Taps "Save changes"
3. Reminder is updated in Firestore
4. Old alarm is cancelled, new alarm is scheduled
5. Modal closes, UI updates (stats may change)

### Delete Reminder

1. User taps a reminder card → Modal sheet appears
2. User taps delete icon (trash button, top-right)
3. Confirmation dialog (optional, future enhancement)
4. Reminder is deleted from Firestore
5. All alarms for this reminder are cancelled
6. Modal closes, UI updates (reminder disappears)

## Troubleshooting

### Reminders not appearing after login

**Symptom**: User logs in, but Reminders screen is empty (no loading state visible).

**Solution**:
1. Check Firestore rules — user must have read/write permission to `users/{uid}/reminders`
2. Verify user's Firestore data exists — check `users/{uid}/reminders` collection in console
3. Call `reminderProvider.refresh()` manually (debug)

### Alarms not firing

**Symptom**: Time passes, no notification appears.

**Solution**:
1. Check device notification settings — MediSense notifications may be disabled
2. Check Android/iOS background restrictions — battery saver may disable alarms
3. Check notification permission — `NotificationService.initialize()` requests permissions
4. Verify time format is valid (e.g., "8:00 AM", "14:30")
5. Test manually: create reminder with time 2 minutes from now, wait

### Duplicate alarms

**Symptom**: Multiple notifications for the same reminder.

**Solution**:
1. Should never happen (IDs are stable, `cancelForReminder()` always runs first)
2. If it occurs, force restart app (triggers `_initializeReminders()` which deduplicates)

### Firestore quota exceeded

**Symptom**: "Quota exceeded" error when saving reminders.

**Solution**:
1. Check Firestore usage limits (free tier: 50k reads/day)
2. Implement client-side caching to reduce reads
3. Upgrade to Blaze billing (pay-as-you-go)

## Code Examples

### Complete Flow: Create, Schedule, and Fire an Alarm

```dart
// 1. Create reminder in UI
final reminder = Reminder(
  title: 'Take medicine',
  dose: '1 tablet',
  time: '8:00 AM',
  schedule: 'Daily',
);

// 2. Save to Firestore and schedule alarm
await reminderProvider.add(reminder);

// 3. Behind the scenes:
// → reminder.id is assigned from Firestore
// → Firestore document created at users/{uid}/reminders/{id}
// → NotificationService.scheduleReminder(reminder) called
// → Native alarm scheduled via FlutterLocalNotifications
// → Alarm ID = (title.hashCode.abs() % 100000) * 10

// 4. Next day at 8:00 AM:
// → OS fires the alarm
// → Flutter notification appears
// → User taps notification (app open or closed)
// → Payload routed to NotificationService._saveFromPayload()
// → Notification logged to JSON history
// → NotificationProvider refreshes UI (if app is open)
```

### Handle Permission Errors

```dart
try {
  await reminderProvider.add(reminder);
} on PlatformException catch (e) {
  if (e.code == 'PERMISSION_DENIED') {
    showToast(context, 'Notification permission required');
    // Can't schedule alarms without permission
  }
}
```

### Listen to Real-Time Changes (Future)

```dart
// Currently not wired up, but available in ReminderFirestoreService:
final service = ReminderFirestoreService.instance;

service.remindersStream().listen((reminders) {
  print('Reminders updated: $reminders');
});
```
