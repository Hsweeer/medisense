# Firestore Schema — MediSense Reminders

## Collection Structure

```
Firestore
└── users/
    └── {uid}/  ← Firebase Auth user ID
        └── reminders/  ← Reminder documents
            ├── {reminderId1}/  ← Auto-generated by Firestore
            │   ├── title: String
            │   ├── dose: String
            │   ├── time: String
            │   ├── schedule: String
            │   ├── instructions: String
            │   ├── addedBy: String
            │   ├── status: String
            │   ├── streakDays: Integer
            │   ├── enabled: Boolean
            │   └── snoozeLabel: String | null
            │
            ├── {reminderId2}/
            │   └── ...
            │
            └── {reminderId3}/
                └── ...
```

---

## Document Schema

### Reminder Document

```json
{
  "title": "Ibuprofen",
  "dose": "200 mg · 1 tablet",
  "time": "8:00 AM",
  "schedule": "Daily",
  "instructions": "With food, after breakfast",
  "addedBy": "you",
  "status": "pending",
  "streakDays": 5,
  "enabled": true,
  "snoozeLabel": null
}
```

### Field Details

| Field | Type | Required | Notes |
|-------|------|----------|-------|
| `title` | String | ✅ | Immutable (locked after creation). Unique ID for alarm scheduling. |
| `dose` | String | ✅ | E.g., "1 tablet", "2 puffs", "200 mg". User-friendly display. |
| `time` | String | ✅ | 12-hour format, e.g., "8:00 AM", "2:30 PM". Parsed by NotificationService. |
| `schedule` | String | ✅ | One of: "Daily", "Weekdays", "Mon · Wed · Fri", "Custom". |
| `instructions` | String | ❌ | Optional. E.g., "after food", "with full glass of water". |
| `addedBy` | String | ✅ | "you" (user-created) or "MedAI" (AI-suggested from prescription scan). |
| `status` | String | ✅ | "pending", "taken", "snoozed", or "skipped". Defaults to "pending". |
| `streakDays` | Integer | ✅ | Current streak count. Resets to 0 if skipped. Defaults to 0. |
| `enabled` | Boolean | ✅ | If false, alarm is cancelled (but data persists). Defaults to true. |
| `snoozeLabel` | String \| null | ❌ | E.g., "rings again in 10 min". Null = not snoozed. |

## Operations

### Create Reminder

**Firestore Action**:
```javascript
db.collection('users').doc(uid).collection('reminders').add({
  title: 'Vitamin D',
  dose: '2000 IU',
  time: '9:00 AM',
  schedule: 'Daily',
  instructions: 'With food',
  addedBy: 'you',
  status: 'pending',
  streakDays: 0,
  enabled: true,
  snoozeLabel: null
})
```

**Return**: Document ID (auto-generated), stored in `reminder.id`

**Alarm**: Scheduled immediately via `NotificationService.scheduleReminder()`

---

### Read Reminders

**Firestore Query**:
```javascript
db.collection('users').doc(uid).collection('reminders').get()
```

**Return**: Array of all reminder documents

**Serialization**: Each document converted via `Reminder.fromMap()`

---

### Update Reminder

**Firestore Action**:
```javascript
db.collection('users').doc(uid).collection('reminders').doc(reminderId).update({
  time: '9:30 AM',
  schedule: 'Weekdays',
  // ... other fields
})
```

**Alarm**: Old alarm cancelled, new alarm scheduled immediately

---

### Delete Reminder

**Firestore Action**:
```javascript
db.collection('users').doc(uid).collection('reminders').doc(reminderId).delete()
```

**Alarm**: All alarms for this reminder cancelled (daily + all weekdays)

---

### Status Changes (No Rescheduling)

**Examples**:
```javascript
// Mark as taken
db.collection('users').doc(uid).collection('reminders').doc(id).update({
  status: 'taken',
  streakDays: 6
})

// Snooze
db.collection('users').doc(uid).collection('reminders').doc(id).update({
  status: 'snoozed',
  snoozeLabel: 'rings again in 10 min'
})

// Skip
db.collection('users').doc(uid).collection('reminders').doc(id).update({
  status: 'skipped',
  streakDays: 0  // reset streak
})
```

**Alarm**: No change

---

### Enable/Disable Reminder

**Enable**:
```javascript
db.collection('users').doc(uid).collection('reminders').doc(id).update({
  enabled: true
})
```
**Alarm**: Scheduled immediately

**Disable**:
```javascript
db.collection('users').doc(uid).collection('reminders').doc(id).update({
  enabled: false
})
```
**Alarm**: Cancelled

## Security Rules

### Recommended Rule

```firestore
service cloud.firestore {
  match /databases/{database}/documents {
    // Users can only read/write their own reminders
    match /users/{uid}/reminders/{reminderId} {
      allow read, write: if request.auth.uid == uid;
    }
  }
}
```

### Why This Works

- `request.auth.uid` = Firebase Auth user ID
- User can only access docs under `users/{their-uid}/`
- Anonymous users cannot access reminders

## Indexing

### Recommended Indexes

For optimal query performance, create these indexes:

**Index 1: By UID (for list queries)**
```
Collection: users/{uid}/reminders
Fields: (Collection ID), enabled (Ascending), title (Ascending)
Scope: Collection
Query Scope: Collection
```

This speeds up:
```
reminders where enabled == true order by title
```

**Note**: Simple collection queries (like `get()` without filters) don't require indexes.

## Data Migration (From Mock to Firestore)

### One-Time Script (If Needed)

If you have existing mock reminders and want to seed Firestore:

```dart
Future<void> migrateReminders(String uid) async {
  final batch = FirebaseFirestore.instance.batch();
  final ref = FirebaseFirestore.instance
      .collection('users')
      .doc(uid)
      .collection('reminders');

  for (final mockReminder in MockData.reminders) {
    batch.set(ref.doc(), mockReminder.toMap());
  }

  await batch.commit();
}
```

**Do NOT call this automatically** — only if you need to restore existing mock data for testing.

## Quotas & Limits

### Free Tier (Default)

- **50,000 reads/day**
- **20,000 writes/day**
- **20,000 deletes/day**

### Typical Usage (10 Users, 5 Reminders Each)

**Daily reads**:
- App startup: 10 users × 1 read = 10 reads
- Status updates: 10 users × 5 reminders × (take/skip/snooze) ≈ 50 reads/writes per day
- **Total**: ~60 reads/day ✅ Within free tier

**Scaling to 1000 users**:
- Startup: 1000 reads
- Status updates: 5000 reads/writes
- **Total**: ~6000 reads/day ✅ Still within free tier

### When to Upgrade

- **1000+ active users**
- **Heavy real-time sync** with `remindersStream()` (read per update)
- **Analytics queries** on reminder adherence

Upgrade to **Blaze (pay-as-you-go)**: $0.06 per 100K reads, $0.18 per 100K writes

## Example Queries

### Fetch All Reminders for User

```dart
final snapshot = await FirebaseFirestore.instance
    .collection('users')
    .doc(uid)
    .collection('reminders')
    .get();

final reminders = snapshot.docs
    .map((doc) => Reminder.fromMap(doc.data(), doc.id))
    .toList();
```

### Fetch Only Enabled Reminders

```dart
final snapshot = await FirebaseFirestore.instance
    .collection('users')
    .doc(uid)
    .collection('reminders')
    .where('enabled', isEqualTo: true)
    .get();
```

### Listen to Real-Time Changes

```dart
FirebaseFirestore.instance
    .collection('users')
    .doc(uid)
    .collection('reminders')
    .snapshots()
    .listen((snapshot) {
  final reminders = snapshot.docs
      .map((doc) => Reminder.fromMap(doc.data(), doc.id))
      .toList();
  print('Reminders updated: $reminders');
});
```

## Troubleshooting

### No Reminders Load After Login

1. Check Firestore rules — user must have `read` permission
2. Check user's `users/{uid}` document exists
3. Check `users/{uid}/reminders` collection exists
4. Use Firestore console to verify documents are there

### Permissions Denied Error

1. Verify security rules are in place
2. Check `request.auth.uid` matches user's Firebase Auth UID
3. Ensure user is logged in (auth token present)

### Slow Queries

1. Create indexes (see Indexing section)
2. Limit subcollection queries with `where()` filters
3. Use pagination for large reminder lists
4. Monitor Firestore usage in Firebase Console
